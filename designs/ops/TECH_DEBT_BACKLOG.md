procedure** — ACCEPTED rows first, top to bottom; then PROPOSED rows by **the highest tier across ALL

`--weekly-threshold 95`, never higher. The live arm's needs always come first; the burn-down uses
what the arm does not.

its own size and says what it waits on. Each row carries its size; an ACCEPTED row also carries its
acceptance test ("done when"). A row is DONE when that test is in the routine suite or its artifact
is on main, and moves to §3 with the commit.

**How this file is organized (keep it this way).** §2 is split into CATEGORY subsections, each one

AND SIZE POSITION — never appended at the bottom of the file**, and never below §3. If no category

LINE at the top of §3 — title, reason, evidence (a commit, a test, a deleted path); never the story,
which git keeps. A PARTLY done row stays, trimmed to what remains. Keep each row's **bold first phrase** (its title) unchanged when editing, so a concurrent edit can find
it. A model / observation / research proposal does not belong here: put it where the first paragraph
