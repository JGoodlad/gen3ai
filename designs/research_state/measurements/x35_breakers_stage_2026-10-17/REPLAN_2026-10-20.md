## 2. The promotion-rule arm (SPRT), to LR-F's depth

- **The ONE lever: `--promotion-sprt`** (T6, built, config v129), C0's argv plus that one flag. Every 2M eval-cycle
  snapshot becomes a CANDIDATE. Each is decided by its own pentanomial GSPRT (the generalised sequential probability
  ratio test over mirrored pairs) on fresh pairs: H0 0.50 against H1 0.55, α = β = 0.05, a cap of 1,680 pairs.
  `--promote-threshold` is not read.
- **Why it freshens the pool.** I simulated `sprt_promotion/simulate.py`'s `simulate()` (τ 1, 5,000 runs, seed
  20261020, under a minute of CPU). At a true edge over the pool of 0.51 / 0.52 / 0.53 / 0.54, SPRT promotes
  **0.10 / 0.32 / 0.66 / 0.90** per candidate. Today's rule (500 games above 0.55, binomial) promotes
  **0.04 / 0.09 / 0.19 / 0.33**. X26 measured ≈ 0.24 per cycle at 280M (6 per 50M), so its noise is above binomial.
  Expect ≈ 2–3× C0's promotions at any edge above 0.51.
- **What it measures that nothing else does.** The accept fraction over ≈ 30 candidates (3 seeds × 10) reads the
  trainee's TRUE edge over its own pool. It goes from 0.10 at an edge of 0.51 to 0.66 at 0.53. A fraction near 0.03
  means an edge ≈ 0.50, which confirms TM-1's "progress stopped, so the pool stopped refreshing". A high fraction
  with no S gain says freshness is not the binding constraint.
- **Predictions to register with a ruling (GUESS, mine):**
  - N_prom ≥ 2 × C0's, pooled, iff the accept fraction is ≥ 0.10;
  - the final median pool age is below C0's 55–76M;
  - Δ_pop is 0.0 pp, 80 % [−1.0, +1.5]. There is a LOSS tail, because near-copies narrow the pool.
- **The frame.** As LR-F: the same side's C0, R1 plus the guards G-F / G-C / G-K, and TM-2's instruments reported.
- **Cost.**
  - ≈ 500 pairs per candidate, ≈ 11 s per 2M cycle on the Rust eval core (from its measured 900 games in 10 s): < 1 % of
    wall.
  - 12.9 GPU-h per side, or + 12.9 if the kit cannot share C0 at a written pin (F-AS-8).
  - The build is a kit arm, ≈ 0.25 agent-day.
- **Validated.**
  - `main.checkargs` exits 0 on C0 + `--promotion-sprt` against P\*'s pinned parser @`9c033489` and on toy C0 +
    `--promotion-sprt` against T\*'s @`ae2d0901`.
  - The dry run was NOT run (no lease, F-LRF-1).
  - T6 still owes its first GPU confirmation.
- **Why it ranks above LR-F.**
  - SPRT's mechanism read is uncertain, so it is informative. LR-F's is set by construction.
  - LR-F's confound role needs a NULL.
  - Toy LR-F tests the lineage whose step size did NOT coincide with its plateau (F-LRF-3), so it should go to
    production.

## 5. What each recommendation risks if the predictions are wrong

X55's P1 missed (14 / 18). Its misses were single edges (±3–5 pp of cyclic noise), and the old nodes were CLOSER to
P\* than predicted. That argues against archive diversity, not for it. Its structural claims held. Read its point
predictions as about 2× too confident. Even with A1's 80 % interval widened to [−2, +3], P(GAIN) stays < 0.1 (my
arithmetic).

- **Deferring P3:** a real 3–4 pp archive effect reads CONTINUE and waits days, with nothing lost.
- **Dropping A2:** if PFSP's form matters, LG-2's promotion to rank 2 is lost. The registered P(GAIN) is ≈ 0.
- **D1 early:** its cost and its effect are unverified, and plasticity at a plateau is a named risk. The order changes
  but the registration does not.
- **SPRT:** the first GPU use of T6 (a test blocks its collect), and a narrower pool (the LOSS tail). The toy-gap run
  de-risks both.
- **LR-F late:** if the step size binds, every batch-1 read was taken at the halved rate. But R1 seldom returns the NULL
  that this would mislabel.
- **X48 late:** if capacity binds, one or two days are lost. X47's class re-orders it.
- **(a):** a ROBUSTNESS GAIN can hide an S loss smaller than R1 resolves (≈ 5 pp). G-F and G-K are the guards.
- **(b):** if the spine has hidden an old Nash node (F-X55-3), the second arm misses it. But P\*'s measured row has no
  old node that beats it.
