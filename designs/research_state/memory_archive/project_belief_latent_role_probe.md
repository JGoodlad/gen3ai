> **Archived 2026-09-08** — ai_v5-era latent-belief design exploration; superseded by the shipped belief stack and designs/ARCHITECTURE.md. Preserved verbatim; nothing below is current.

2026-06-13 design exploration (NOT built) of a **latent/BYOL escalation for the hidden-opp belief aux head** ([[project_hidden_team_belief_built]]) + an empirical **role-geometry probe** that grounds it. Goal was the user's: let the belief head predict a *role* (Spiker / bulky-water / sweeper) in latent space, not a rigid species id; same for moves (offensive/support/phazing).

**DESIGN CONCLUSIONS (first-principles, teaching):**
- BYOL's headline benefit (label-free) does NOT apply — we HAVE privileged labels. The real buy of a latent target = **off-schema richness** (item/EV/archetype the species+move-id schema can't encode) + graded similarity (CE treats all wrong species equally; cosine-to-embedding makes "a similar wall" less wrong).
- **A latent is NOT automatically a role space** — what it encodes = the TARGET's metric geometry + what you force invariance to. "Role" = predict-WHERE-in-a-space-whose-distances-mean-function, not predict-WHICH-class.
- **Vanilla continuous latent + cosine regression toward the (stop-grad) encoder role token, interpreted post-hoc via k-NN to real mons, is the right v1.** NO prototypes / NO K during exploration — prototypes add a hyperparam (K) AND a collapse mode (prototype collapse). Defer discretization to analysis time (cluster/k-NN), it's strictly more flexible. k-NN-to-nearest-real-mons IS the correct interpretability tool (word2vec-style).
- **Collapse is mostly DEFUSED here** without the full BYOL stack: the target encoder is task-anchored (shared with policy/value/damage heads → Aero≠Blissey can't collapse). SimSiam-style stop-grad (no EMA) likely suffices. **InfoNCE/contrastive ≥ BYOL when you have identity** (you can build real negatives → collapse-proof by construction; ai_v5 doc already flagged it "often the better choice here"). **MSE forbidden under PopArt → cosine only.** VICReg variance+covariance floor = cheap bolt-on collapse insurance + `latent_std→0` NO-GO monitor.
- Sibling-not-same as ai_v6 Stage-5a BYOL (that predicts ACTION-OUTCOME latents + carries the value-path-leak STOP-flag); belief-BYOL predicts hidden IDENTITY. Both are pre-cut seams: `BeliefHead.forward` returns a dict so a `"latent"` key slots in; `_belief_aux_loss` Hungarian `best_perm` is reusable for embedding-space matching.

**ROLE-GEOMETRY PROBE (ran on ai_v5_11 ~52M ckpt, 177 real OU sets/75 species, pre-transformer 128-d role token; script in workflow worktree, NOT saved to repo):**
- ✅ **SPECIES/ARCHETYPE geometry is STRONG & graded.** k-NN type-Jaccard gap +0.292 (kNN 0.365 vs rand 0.073) = **~7.5× the raw-107d-input control's +0.039** → the trained encoder AMPLIFIES function, not pass-through. Neighbors coherent: suicune→vaporeon/milotic/kingdra, skarmory→forretress/cloyster/steelix, blissey→porygon2/chansey/starmie, salamence→charizard/moltres. Linear-probe AUC 0.80–1.00 for all roles; emb>raw for moveset-driven roles (hazard_setter 0.99 vs 0.92, phazer 0.87 vs 0.77, trapper 1.0 vs 0.92). **⇒ regression target is meaningful — your latent-role intuition is VALIDATED at the representation level.**
- ⚠️ **HONEST CATCH #1:** for pure-STAT roles raw input is MORE separable than emb (setup_sweeper 0.93 raw vs 0.81 emb) → revealed-mon role is TRIVIALLY in the obs (computed from provided stats/types/flags). So **decodable-from-a-revealed-mon ≠ belief head helps**. The belief head's value is ONLY in UNREVEALED slots (no input to pass through). Probe is necessary-not-sufficient: confirms TARGET space has role structure, does NOT test whether INFERENCE is learnable. "Linearly decodable" and "adding it helps" are different claims (same trap as [[project_loss_triage_tool]] critic_blindspot overturn).
- ⚠️ **MOVES: role geometry ABSENT from the learned move-ID embedding table** (offensive/support/phazing AUC ~0.51–0.55, flat). WHY (deep principle): **a representation only encodes what isn't already handed to it** — the move-id vector feeds the move-net ALONGSIDE explicit BP/type/category/effect-flag scalars, so zero pressure to re-encode offense/support. (Flip side of [[feedback_provide_vs_learn]]: provide a fact explicitly → model won't redundantly re-encode it.) NUANCE: probe tested the THIN 16-d id LOOKUP, not the move-net's COMPOSED output (which ingests BP/category and likely DOES separate). ⇒ move-role richness won't come free from the id table; build it from a COMPOSED moveset representation + regress toward that (not predict-4-move-ids BCE).

**FOLLOW-UP PROBES (2026-06-14, ai_v5_11 52M, 2 probes ran):**
- **Composed move-token HAS the role geometry the id-table lacked (CONFIRMED).** Tapped the 32-d output of `ext.pokemon_encoder.move_network` (forward hook): offense/support AUC 0.75/0.76 + kNN coh 0.583, vs the bare 16-d id table at chance (0.51/0.59, coh 0.510). ⇒ a continuous move-belief should regress toward the COMPOSED token, NOT the id lookup. Caveat: partly pass-through (the move-net concats explicit BP/secondary/recoil scalars into the 32-d token), so it's "provided structure in geometric form," not a discovered abstraction.
- **The trunk does NOT internally compute OUTGOING damage magnitude.** 400 attacker×defender actives, ground-truth via a verified gen3 damage calc: internal reps (pi/vf/active-token) recover best-move damage-fraction R²~0.30 + KO-AUC~0.80 — WORSE than a linear probe on the raw obs ingredients (R² 0.42, AUC 0.885). Transformer composes a partial matchup signal (pre-transformer 0.12→0.30) but ends LOSSIER than its inputs — compresses damage magnitude away. Reproduces the old damage-spread r²~0.06 on the outgoing side. (Caveat: synthetic board zeroes the live 288-d matchup block, so eff-anchor isn't near-1; but internal<raw is measured same-board ⇒ robust.)
- **JOINT PATTERN (key principle):** the trunk PRESERVES low-dim CATEGORICAL structure (move role, type) but COMPRESSES AWAY high-res CONTINUOUS magnitudes that need multiplicative composition (BP×STAB×eff×stat-ratio = damage). This is empirical proof of "compute deterministic magnitudes & provide them; don't make the trunk learn them" — exactly why incoming-damage is a provided feature (works) and outgoing is not (model flails).
- **ARCHITECTURE CONCLUSION for belief→damage (answers the CPU/GPU question):** damage calc currently runs in the CPU obs-build (state_encoder, ~88% CPU, env-worker proc); belief is a GPU model output → can't feed the CPU calc same-decision without a cross-proc round-trip. Options: (A) learned-internal [NOW FALSIFIED by probe 2 — trunk can't], (B) two-pass belief→CPU-recalc→re-forward [hits CPU bottleneck, collapses the distribution, ~search-ish], (C) CPU usage-prior marginal [today, flat], (D) **RECOMMENDED = differentiable damage op ON THE GPU fed by the belief's SOFT distributions** (type-chart/BP as fixed tensors) → expected damage under the belief, single-pass, uses idle GPU (GPU 86% idle, CPU is the bottleneck), preserves the distribution. Independent evidence FOR the gen3_outgoing_ko_v1 lane (obs gap AND representation gap). General principle: learn the epistemic (belief over identity), COMPUTE the deterministic (damage/effectiveness/status-flags), represent the aleatoric (rolls/crits) as distributions — three separate objects.
