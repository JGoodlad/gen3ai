# `scripts/ops/`: operational instruments for runs, the GPU and the box

The watchers, reads and locks that `designs/ops/TRAINING_RUN_SOP.md` and the root rules name. Every script prints
its usage and exit codes on `--help`; this page says what each is for and the hazard `--help` would not make plain.

**Two halves.** The shell scripts are OS processes: they run under `nohup`, survive a dead Claude session and are
the record of an unattended period. The Python instruments live in [`src/main/ops/`](../../src/main/ops/) so they
are importable and testable.

**Every one refuses rather than defaults.** No argument does not mean "the usual run"; a missing scalar is not a
zero; an absent archive is not an empty one. `src/main/ops/ops_scripts_test.py` holds that line for the shell layer
(`bash -n`, `--help`, bare-invocation refusal, no `/home` literal).

---

## Run instruments

| script | what it is for, and the hazard |
|---|---|
| [`watch_run.sh`](watch_run.sh) | SOP §2 layer 1: polls a run's step progress, bounds the idle gap (`--wedge-seconds`), matches ANCHORED failure lines (never the bare words: they false-fired on warnings and banners), checks the arm-invalidating `--sync-to-main` line, and appends one status line per tick with MARGINAL fps. **Give it `--launcher-log`**: the launcher restarts a crashed child by itself, so the launcher log is the authority (`CRASH:` / `RESUMED:` events; it ends only on `DONE:` or `FAILURE:`); without one, the first child-log error ends it. A Monitor filter wants `CRASH\|RESUMED\|DONE\|FAILURE\|WATCHER EXIT`. Started beside a launch it waits for `models/<run>/` (`--dir-wait-seconds`). |
| [`marginal_fps.sh`](marginal_fps.sh) | The standard throughput meter: `(steps_N - steps_{N-1}) / (mtime_N - mtime_{N-1})` per consecutive checkpoint pair. Never SB3's cumulative `time/fps` (it lags every regime change) and never the integer-`fps` derivative (it explodes at high step counts). It prints `train/selfplay_fraction` beside each figure because an fps on a self-play arm is a function of it. |
| [`restart_read.sh`](restart_read.sh) | The registered first-restart read (SOP §3): the vf_coef statistic and verdict from the TB EVENTS (`main.ops.tb_read`; the bar is imported from `vf_framings`), then `main.sidecar_audit` (the pin must be unchanged), the restart evidence, `killbar`, `vf_framings`, `restart_startup`. The child log's table is a labelled CROSS-CHECK only (a ~1 MiB ring buffer that trims silently): it prints both medians, warns on a large difference and never decides. A single-sample reading is never a verdict; every section reports the window median. |
| [`s_read.py`](s_read.py) | The paired speed benchmark's cost read: `s = median(alt) / median(base) - 1` over update-cycle walls, eval / canary / stop / contended cycles excluded. A pair with no quiet cycles is REPORTED as `insufficient quiet cycles`, never a crash; the pooled `s` is then `null` and the exit is 3. |

## GPU, gates and memory

| script | what it is for, and the hazard |
|---|---|
| [`gpu_lease.sh`](gpu_lease.sh) | The GPU lease (root rule 5): `acquire --owner <name>` takes it NOW or fails AT ONCE naming the holder (exit 6 leased, 5 a one-off hold); on success stdout is `export GEN3AI_GPU_LEASE_TOKEN=<token>`. A detached holder keeps the flock `gpu_lock.sh` uses until `release`, SIGTERM, `--max-hours` or `--watch-pid`'s death; `--watch-pid` must be a LIVE long-lived pid (a `nohup setsid ... &` wrapper pid is refused, exit 2). A lease whose holder is dead or whose pid was reused is STALE and cleared by `status` / `acquire`. `release` is idempotent and needs the token (env or `GEN3AI_GPU_LEASE_TOKEN_FILE`); exit 7 = not yours; `--force` is the orchestrator's. Wrapper over `src/utils/gpu_lease.py`; tests `src/utils/gpu_lease_test.py`. |
| [`gpu_lock.sh`](gpu_lock.sh) | The ONE way a shell runs a command on the GPU, fail-fast: the lease token passes straight through; someone else's lease exits 6 at once (even with `--wait`), a one-off holder exits 5 unless `--wait` (the orchestrator's or a training launch's). **Preempt a job with `kill -TERM -- -<pgid>` on the command's own process group**, never the wrapper's pid: the pgid is logged at start and shown by `--status`. A wall timeout goes INSIDE (`gpu_lock.sh timeout 3000 <cmd>`), never outside (that counts lock-wait time). A nested take verifies its marker, so a forged `GEN3AI_GPU_LOCK_HELD` cannot bypass the lock; a `--wait` on a lock held by its own ancestor raises exit 3 at once. Lock file `~/.claude/jobs/gpu.lock` (`$GEN3AI_GPU_LOCK`). Wrapper over `src/utils/gpu_lock.py`; tests `src/utils/gpu_lock_test.py`, `src/utils/procgroup_test.py`. |
| [`gate_lock.sh`](gate_lock.sh) | The routine gate's semaphore: runs `<cmd>` holding one of N `flock` slots (N declared in `src/utils/gate_lock.py`, one gate at a time per `designs/ops/testing.md`; `$GEN3AI_GATE_SLOTS` overrides). Re-entrant (all slots held by ancestors = exit 3); `--timeout-s` (exit 4) also bounds the heavy-slot wait inside the gate. `--status [--json]` names each holder, its ETA and its queued takers. A live trainer gets a one-line rule-5b warning about this gate's shape, never an action. Tests: `src/utils/gate_lock_test.py`. |
| [`ship_gate.sh`](ship_gate.sh) | THE gate before `/gen3ai-ship`: `ship_gate.sh run` runs the whole routine set (`-m "not slow and not e2e"` over `src/`, static gates included, never a selection by the change) through `gate_lock.sh` + `mem_cap.sh` with `CUDA_VISIBLE_DEVICES=""`, in the shape the box affords (a live run or a held lease means rule 5b; otherwise the quiet shape). `--dry-run` prints the resolved command; pytest options go after `--`. Shape and cost: `designs/ops/testing.md` "The SHIP GATE"; code `src/utils/ship_gate.py`. |
| [`mem_cap.sh`](mem_cap.sh) | **Any exploratory or one-off HEAVY job runs under it** (traces, benchmarks, measurement drivers, many checkpoints): `mem_cap.sh [--name N] [--max-s S] <GB> <cmd...>`. The cap is VERIFIED in the job's own cgroup before the command starts (a cap not in force is exit 85, never an uncapped run); jobs share one aggregate slice (`--slice-gb`), `oom_score_adj` is raised so a box-wide OOM picks a heavy job over Claude, and a slice-level kill is exit 86 (a memcg race can take a sibling too: the slice cap is a backstop, never a scheduler). **Stopping:** a `timeout` OUTSIDE (`timeout 3000 mem_cap.sh 12 ...`) bounds the whole wrapper and does stop the job: signals are forwarded to the command, and `--term-grace` seconds after the first one the supervisor SIGKILLs every process left in the scope, `setsid`-ed workers included (exit 143 on SIGTERM, 137 once the grace killed it). Not covered: a command that exits normally leaving a detached process in the scope (`--status` lists it). **Heavy slots** (`src/utils/heavy_slots.py`; rule 5b's "<= 2 heavy jobs"): while a run is live OR the GPU is leased, the job first takes one of the box's slots, waiting FIFO per lane (`--no-wait` refuses at once, exit 87); hold a slot per BOUNDED CHUNK (<= 45 min), never per run (`--status` flags a longer hold). **Short lane:** `--max-s S` (<= 600) lets a job jump a queued long job, in return for a HARD kill at S + 30 s, exit 88 (re-queue it as a long job); the deadline binds only a job that took a slot of its own. A job the orchestrator marks BLOCKING (`$GEN3AI_BLOCKING=<why>` or `--blocking`) bypasses the slots. A job already under `gpu_lock` takes no CPU slot, so the GPU never idles behind a slot wait. **Lock order: `gate_lock.sh` OUTSIDE `mem_cap.sh`.** Tests: `src/utils/mem_cap_test.py`, `src/utils/heavy_slots_test.py`. |
| [`rebuild_main_rust.sh`](rebuild_main_rust.sh) | Rebuild MAIN's Rust target after a ship that touched `src/rust_sim` / `src/rust_env` (`/gen3ai-ship` step 9): since the build stamp, those ships leave main's binaries REFUSED until rebuilt. `run` REFUSES while any live process maps or runs an artifact under main's `src/rust_*/target` (it never kills it) and while main is dirty, builds the four artifacts, then verifies each `--build-stamp` against main's tree. `--check` verifies only; `--dry-run` prints the plan. Exit codes: `src/utils/rebuild_main_rust.py`. |
| [`_common.sh`](_common.sh) | Sourced, not executed: repo root, MAIN checkout, `models/` (mirrors `utils.paths.main_models_dir()`, `$GEN3AI_MODELS_DIR` authoritative), run resolution, the interpreter. |

## Agent-waiter and box hygiene (stdlib only, read `/proc`)

| script | what it is for, and the hazard |
|---|---|
| [`idle_waiter_watchdog.py`](idle_waiter_watchdog.py) | An ON-DEMAND diagnostic for stuck background waits (`ORCHESTRATOR_SOP.md` §7.w): prints nothing and exits 0 when all is well, one line per flag and exit 1 otherwise (2 = its own error). It flags a SELF-DEADLOCK (blocked on a lock whose holder is its own ancestor), an IDLE-WAITER (a poll loop or `flock` whose subtree and wait targets show no progress), a DUPLICATE-WAITER (identical waiters in one session) and a BIG-RSS uncapped process (`--rss-gb`). A `mem_cap` scope's growth is only INFO, printed by `--status` (read-only, writes no state). Never kills. **Nothing runs it on a schedule (the owner retired its cron): run it by hand when an agent looks hung, and do not re-create the cron unasked.** Tests: `src/main/ops/idle_waiter_watchdog_test.py`. |
| [`tmp_sweep.py`](tmp_sweep.py) | The `/tmp` sweep (a RAM-backed tmpfs with a fixed inode table that can hit ENOSPC on inodes with bytes free). DRY RUN by default; deletes only with `--apply`; always exits 0. A top-level entry goes WHOLE only when it is owned by the uid, not on the KEEP list, older than `--min-age-hours` by its newest inner mtime, and referenced by no live process (cwd, fd, map, environment, bound socket); compile caches are file-pruned by `--cache-max-age-hours` instead. Symlinks are never followed. Tests: `src/main/ops/tmp_sweep_test.py`. |

## One-shot: the git history rewrite (DRY RUN tooling only)

| module | what it is for, and the hazard |
|---|---|
| `python -m utils.history_rewrite` | The account-name purge, as a dry-run kit (runbook `designs/ops/history_rewrite.md`): derives the names OUTSIDE the repo (mode 0600; stdout speaks of `#NN`, never a name), audits all history, builds the `git filter-repo` rules, rewrites a throwaway CLONE (`rewrite` / `dryrun`; the source and every ref of the real repo are only read), writes the old->new SHA map, rewrites SHA citations in tracked text files (`cite`; a prefix of exactly one rewritten commit, else untouched or REFUSED), verifies, and reports what cannot be re-pointed (`report`, `local-plan`). **It never pushes**: the force-push is the runbook's, by hand. Runs at nice 19 (`--cpus 5-7,13-15` for rule 5b); a clone + rewrite is ~15 min of one core. Tests: `src/utils/history_rewrite/*_test.py` (the end-to-end ones need the pinned `git-filter-repo`, cached or fetched with a sha256 check). |
| `python -m utils.git_sha <sha>...` | Resolves a commit SHA cited by an immutable record (a run sidecar's `original_command` / `pin_history`, a frozen ledger entry, a tag NAME) across the rewrite: `designs/ops/history_rewrite_sha_map.tsv` first, git second; ambiguity is reported (exit 2), never picked. Empty map = plain `git rev-parse`. |

## The Python layer: `src/main/ops/`

Every ENTRY POINT is `python -m main.ops.<name>` and prints its contract on `--help`; `run_ref` is a library module
(a run NAME or DIRECTORY to the directory, refusing when there is no archive) with no `--help`.

| module | what it reads, and the hazard |
|---|---|
| `arm_chain` | THE ARM CHAIN (`python -m main.ops.arm_chain`; design and cut-over checklist `designs/ops/arm_chain.md`; **live since 2026-10-26**): one persistent supervisor per chain file of arms (each at its OWN pin) and GPU windows; pre-launch through the X35 kit with its dry run re-verified (FORK, pin, card visible), GO, the post-spawn banner / throughput guards, the arm end (completeness, K9(b) into a SCRATCH stage, the thin, the dose), the records-only ship from a copy (asynchronous, `ship-records`, once the kit's `k9b-batch` writes outside main), and the hand-off; each arm registers `on_void` / `on_throughput_fail` (`stop` | `page`). Also `live` (runs from launcher argv, never a glob), `canary` (every non-PASS alerts; dumps archived), `monitor` (the alert follower: no re-arm at a GO, pages a dead supervisor) or `watch-files` + `monitor-filter` (the `tail -F` fallback), `cpu-gate`, `wait-pid` and `signal-if` (`/proc` identity, never `kill -0`). `status` prints the supervisor ALIVE / STALE / DEAD first. A HOLD stops it (exit 3) and only `clear-hold --resolution retry|relaunch|accept` / `abandon` move it on. Start the supervisor at nice 0: a GO inherits its niceness. |
| `tb_read` | A run's registered scalars from the TENSORBOARD EVENTS, not the child log's table. **A FORK reads its OWN steps only**: every live-tier TB reader (`tb_read`, `killbar`, `stall_exhibit`, `vf_framings`, `restart_startup`) goes through `run_ref.scalar_events`, which cuts the inherited prefix at the lineage record's `fork_step` and REFUSES a boundary the record cannot confirm; `--include-inherited` keeps it. A missing tag WARNS and exits non-zero. It also exports `selfplay_crossing_step`: `step` (the first `*_pool` scalar) and `promotion_step` (the first pool snapshot or self-play fraction) are NOT the same step; a run that never crossed reports `None`, never 0. Descriptive: no floor, no verdict. |
| `killbar` | The kill bars as an AND-gate, clause 2 a fixed effect size evaluated only inside one opponent regime, against a reference frozen once per regime. The frozen references live beside the RUN (`<run>/ops_frozen_refs.json`) and are written only under an explicit `--freeze`; a frozen entry is never rewritten. |
| `vf_framings` | `grad/value_policy_logratio` under all three framings with the registered one named, per-bucket by regime, and the ratio's components so a denominator walk cannot look like the critic sharpening. |
| `restart_startup` | A restart's startup cost: the TB wall-time gap across the boundary minus the steady cadence, against a pre-registered reading and a baseline file. |
| `plateau_signal` | The two-clause ladder plateau REPORT trigger. Never a kill. |
| `stall_exhibit` | `ep_len` and `draw_rate` per bucket on the same rows, the table that separates a stall from a competence sawtooth. |
| `perbot_r`, `perbot_rank` | Pearson `r(base, skill)` (battle-clustered bootstrap) and the same claim as a Spearman ordering (bootstrap clustered by opponent). |
| `negskill_null` | The null for a count of negative-skill cells: a perfectly calibrated critic with the head's own forecasts scores negatives by chance at these n. |
| `eval_trace_gen` | Regenerates an eval-traces cycle for a SAVED checkpoint, offline on CPU at any size, by playing a `ShardedEvalPool` plan on the Rust eval core (the same executor a live cycle uses). Default capture is ALL. The regime is READ from the run's recorded eval settings (a run that recorded none is REFUSED). **A specialist's team pin is recovered from `metadata.json`** (`recover_trainee_pin`), never from `model_config.json`; a declared pin that cannot be recovered is REFUSED, never defaulted to the pool. Core traces record no win-prob head, so a reader that needs one refuses a generated cycle. **Nothing is ever written under `models/`**: the cycle is a self-contained shadow run dir; its manifest's `generated_by` block records the tool, regime, compute flags, seed and checkpoint sha. The seed does not pin the batched forward's rounding (a near-tie decision can flip under other compute flags; the count is recorded). |
| `value_sidecar_read` | The TRAINING-SIDE calibration read: the critic against its OWN training target from `<run>/value_sidecar/rows.jsonl` (Murphy decomposition and skill, episode-clustered bootstrap CIs). It reads the HEADER FIRST and labels every table with what `target` is; it refuses a run with no sidecar, a headerless one, a `shaped` one without `--allow-shaped`, a file whose `target` changes meaning mid-way, and a `--compare` whose headers disagree. A disagreement with the eval-battle reads is a generalisation finding, not an error. |
